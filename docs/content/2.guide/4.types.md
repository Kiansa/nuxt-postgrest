Clients are typed from a `Database` type in the format produced by `supabase gen types typescript`. The module reads it from `types.path` (default `~~/shared/types/database.types.ts`). Without the file, clients are untyped.

```ts
const { data } = await usePostgrest().from('todos').select('id, title')
//      ^? { id: number, title: string }[] | null

usePostgrest().from('todo') // ❌ compile error: unknown table
```

## Generating the file

The generator only needs a Postgres connection string. It does not depend on Supabase hosting.

### Automatically on `nuxt dev`

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  postgrest: {
    types: {
      generate: true,
      schemas: ['public', 'api'],
    },
  },
})
```

```bash [.env]
NUXT_POSTGREST_DB_URI=postgres://postgres:postgres@localhost:5432/postgres
```

Types are regenerated on `nuxt dev` and `nuxt prepare`. This requires Docker, because the Supabase CLI runs its introspection in a container. Generation never runs during `nuxt build`, so CI and production builds use the committed file.

::note
If generation fails, the existing file is kept and a warning is logged. Your dev server still starts.
::

### Manually

```bash [Terminal]
npx supabase gen types typescript \
  --db-url "$NUXT_POSTGREST_DB_URI" \
  --schema public > shared/types/database.types.ts
```

Commit the generated file so builds don't need database access.

## Non-default schemas

Include each schema in `types.schemas`, then target it:

```ts
usePostgrestAdmin().schema('internal').from('audit_log').select('*')
```
